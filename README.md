# Tourist Report

MVP для керівників туристичних груп на SvelteKit 5. Допомагає вести тури, туристів та екскурсії й готувати дані до звітності.

Застосунок працює як клієнт REST API (NestJS, Swagger — `http://localhost:3000/api/docs`): усі дані та фото чеків зберігаються на сервері, а вхід обов'язковий.

## Можливості

- CRUD для турів, туристів та екскурсій;
- окрема сторінка перегляду кожної сутності з навігацією по зв’язках;
- глобальний пошук по всіх сутностях (⌘K / Ctrl+K);
- фото чеків до екскурсій (стискаються перед завантаженням і зберігаються на сервері);
- ціна екскурсії, статус «Очікує / Відбулася / Не відбулась» та оплата кожного учасника;
- розрахунок по туру: сума лише за екскурсіями, які відбулись;
- друкований звіт по туру (`/tours/[id]/report`) із збереженням у PDF через діалог друку;
- повнорозмірний календар минулих і майбутніх турів та екскурсій;
- зв’язки «тур → багато туристів» і «тур → багато екскурсій»;
- автоматичне очищення зв’язків після видалення сутності;
- пошук і dashboard з основними показниками;
- адаптивний desktop/mobile інтерфейс;
- українська й англійська локалізація через Paraglide JS;
- вхід і реєстрація за email та паролем, сесія переживає перезавантаження сторінки;
- сповіщення (toast) про результат кожного запиту та стани завантаження на всіх діях;
- встановлення як PWA (офлайн доступна оболонка застосунку, дані потребують мережі).

## Архітектура

Структура feature-oriented, адаптована з FSD:

```text
src/lib/
├── shared/       # HTTP-клієнт і API-ресурси, утиліти, реєстр маршрутів, базовий UI
├── entities/     # Tour, Tourist, Excursion, Attachment, User та їх типи
├── features/     # авторизація, сповіщення, форми, глобальний пошук і бізнес-store
└── widgets/      # dashboard, навігація, списки та сторінки перегляду
```

Маршрути — стандартний файловий роутинг SvelteKit: `/tours` (список) і `/tours/[id]`
(перегляд), аналогічно для туристів та екскурсій. Усі URL будуються в
`shared/model/navigation.ts` через `resolve()`, тому route-id перевіряються на етапі
компіляції. Стор створюється один раз у `+layout.svelte` і роздається через Svelte context.

`shared/api/http-client.ts` — єдиний модуль, який викликає `fetch`: він підставляє bearer-токен, зводить будь-яку помилку до `ApiError` і при 401 завершує сесію. `TourReportStore` лишається єдиним місцем, де змінюються доменні дані; компоненти ніколи не звертаються до API напряму.

Гейт авторизації живе в `+layout.svelte`: поки користувач не увійшов, замість оболонки рендериться екран входу, а URL не змінюється — тому глибоке посилання продовжується саме після входу.

PWA використовує нативний service worker SvelteKit. Для встановлення на телефоні production-версія має бути доступна через HTTPS.

## Розробка

Спершу має бути запущений бекенд на `http://localhost:3000`. Адреса налаштовується
через `VITE_API_BASE_URL` — скопіюйте `.env.example` у `.env`, якщо потрібне інше значення.

```bash
npm install
cp .env.example .env
npm run dev -- --strictPort
```

`--strictPort` тут не випадковий: CORS бекенда за замовчуванням дозволяє лише
`http://localhost:5173`, тож якщо Vite перейде на інший порт, браузер заблокує всі запити.

Перевірки:

```bash
npm run check
npm run lint
npm run build
```
